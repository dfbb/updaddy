# updaddy macOS GUI 设计规格

日期：2026-09-03  
最后更新：2026-09-04  
状态：设计已在对话中确认，待书面规格审阅

## 1. 产品定位与首版范围

`updaddy` 是一个面向最新 macOS Apple Silicon 的桌面应用，用统一界面检查和更新本机全局开发工具包。应用采用 Rust + Tauri 2，主窗口关闭后继续驻留状态栏，并支持登录时自动启动。

首版支持五个生态：

- Homebrew：formula、cask、tap
- npm：全局安装的 npm 包
- pip：当前选定 Python 环境中的全局包
- Gem：当前 `gem` 环境中的全局 gems
- rustup：已安装的 Rust 工具链、组件和目标平台

首版不支持 Yarn、uv、Cargo 全局二进制和项目依赖文件。应用不修改项目目录中的 `package.json`、lock 文件、`pyproject.toml` 或其他项目级依赖文件。

首版成功标准：

1. 用户可以扫描五个生态并看到每个生态的更新数量、版本、资源类型和每个软件包的磁盘占用。
2. 用户可以逐包更新或卸载，也可以从概览或状态栏执行跨生态手动“一键更新”。
3. 不同资源锁组可以并行更新，同一锁组内保持串行，避免全局环境竞争。
4. 用户可以取消运行中的任务；已完成任务不回滚，未开始任务被标记为已取消。
5. 仅对网络超时、代理断连和服务端临时错误自动重试；确定性错误不自动重试。
6. 单个 SOCKS5 代理可覆盖所有支持的工具；HTTP-only 工具通过本地 HTTP-to-SOCKS5 桥接访问代理，代理异常时不得静默直连。
7. 支持每日或每周固定时间的后台更新；Mac 睡眠错过计划后，在唤醒或下次启动时补执行一次。
8. 主窗口、状态栏和历史页面显示一致的任务结果；详细日志保留 90 天。
9. 每个生态只进行一次全量软件包发现；磁盘占用使用缓存，首次发现、缓存缺失、安装路径变化或软件包更新后才重新计算单个软件包。
10. 用户隐藏某个生态后，该生态暂停完整扫描且不计入状态栏总数；应用启动时只对隐藏生态做轻量工具探测。
11. 扫描、更新或卸载任务执行期间，前台所有扫描/更新/卸载操作按钮置灰；当前任务的取消按钮始终可用，并在对应生态 tab 顶部显示进度。
12. 支持跟随系统、浅色、深色主题，以及英文和简体中文界面。

## 2. 架构决策与取舍

### 2.1 选定方案

采用 Tauri 单应用 + Rust 核心编排器：

- 前端使用 React、TypeScript 和 Vite，借鉴 `3rd/Depvault` 的技术栈和扫描结果展示方式。
- Rust 后端负责领域模型、包管理器适配器、任务调度、子进程执行、代理桥接、SQLite 持久化和 macOS 生命周期。
- 前后端通过 Tauri command 发起操作，通过 Tauri 事件通道接收任务状态、进度和日志事件。
- 主窗口隐藏后，Rust 运行时和状态栏保持活动；从状态栏退出时才停止调度器并结束进程。

### 2.2 备选方案

曾考虑将 `topgrade` 作为外部执行引擎，或拆分为独立后台服务。前者依赖终端输出格式，难以可靠支持逐包状态、取消、重试和代理事件；后者需要额外的服务安装、IPC 鉴权和版本兼容协议。`topgrade` 的升级步骤编排思想保留在适配器设计中，但不直接嵌入为 GUI 后端。

## 3. 模块边界

Rust 后端按职责拆分为以下模块：

| 模块 | 职责 |
| --- | --- |
| `app-core` | 包、资源、批次、任务、状态、错误和执行结果等领域模型 |
| `adapters` | Homebrew、npm、pip、Gem、rustup 的检测、扫描、计划和执行 |
| `scheduler` | 手动任务、计划任务、补执行判断、资源锁和受控并行 |
| `workers` | 为每个生态维护独立后台 worker，串行处理该生态的扫描、更新、卸载和磁盘测量 |
| `executor` | 子进程启动、环境注入、输出采集、超时、取消和退出码处理 |
| `proxy` | SOCKS5 配置、健康检查和 HTTP-to-SOCKS5 本地桥接 |
| `persistence` | SQLite 迁移、事务、快照、批次、日志和三个月清理 |
| `platform` | macOS 状态栏、窗口隐藏、登录项、睡眠/唤醒和应用退出 |
| `frontend` | 概览、五个生态 tab、历史日志、设置、主题和语言切换 |

适配器只返回结构化数据和日志事件，不直接访问 UI。所有外部命令都必须经过 `executor`，以保证代理、脱敏、取消和错误分类路径一致。前端 command 只负责提交操作并立即返回任务 ID，状态、进度、磁盘占用和日志均通过 Tauri 事件通道推送；不使用独立 HTTP/WebSocket 通信，也不使用前端定时轮询。前端重新打开或从后台恢复时，可调用一次状态快照 command 补齐错过的事件。

## 4. 前后端数据流

### 4.1 扫描

1. 前端调用扫描全部或指定生态的 Tauri command。
2. `scheduler` 将扫描请求投递给对应的生态 worker；五个可见生态的 worker 可以并行执行。
3. 适配器通过 `executor` 检查可执行文件、版本和更新列表。
4. 扫描结果转换为 `package_snapshots`，磁盘测量服务按缓存策略补充占用值，同时推送生态状态、包列表和磁盘占用事件。
5. 前端更新对应 tab 和概览总数；状态栏显示五个已启用生态的合计数量。

### 4.2 更新与卸载

1. 用户触发单包更新、单包卸载、单生态批量更新或跨生态一键更新。
2. 系统基于最新扫描快照创建 `OperationBatch` 和 `PackageTask`，command 立即返回任务 ID。
3. `scheduler` 将任务投递给对应生态 worker；跨生态 worker 根据资源锁并行运行。
4. `executor` 启动命令，实时通过 Tauri 事件推送状态和日志；适配器负责解析包级结果。
5. 任务完成后写入尝试记录和批次摘要，前端、历史页面和状态栏同步结果。

### 4.3 独立生态 worker 与事件通道

`WorkerSupervisor` 为 Homebrew、npm、pip、Gem 和 rustup 各维护一个独立的长期后台 worker。worker 运行在独立线程中，拥有自己的操作队列和生态级资源锁；同一生态内的扫描、更新、卸载和磁盘测量按队列串行，互不阻塞其他生态 worker。

前端 command 只负责向 worker 投递 `Scan`、`Update`、`Uninstall` 或 `RefreshDiskUsage` 消息并返回任务 ID。worker 通过 Tauri 事件发送 `worker-state`、`task-progress`、`package-changed`、`disk-usage`、`log-entry` 和 `batch-summary` 事件。任何任务运行时，前端把所有扫描、更新、卸载、刷新和一键更新按钮置灰；对应活动生态 tab 顶部显示进度条和取消按钮。取消按钮始终可用，窗口关闭和 tab 切换不停止后台任务。

## 5. 任务模型与执行策略

### 5.1 统一任务模型

每个 `PackageTask` 包含：

- 操作类型：更新或卸载
- 生态和资源类型
- 包名、当前版本和目标版本
- 执行步骤和资源锁键
- 状态：排队、运行中、成功、失败、已取消或跳过
- 自动重试次数
- 退出码、错误分类、日志引用和时间戳

一次手动/计划更新或卸载操作称为一个 `OperationBatch`，批次保存整体状态和各任务之间的关联。扫描和磁盘测量任务也使用相同的 task 状态事件，但不计入更新批次。

### 5.2 资源锁

- Homebrew formula、cask、tap 共用 `brew` 锁。
- npm 全局包使用 `node-global` 锁。
- pip 全局包使用 `python-global` 锁。
- Gem 全局包使用 `ruby-global` 锁。
- rustup 使用独立的 `rustup` 锁。

不同锁组可以并行运行；同一锁组内严格串行。扫描阶段是只读操作，可以并行，不持有更新锁。

### 5.3 取消

取消批次时，调度器阻止尚未开始的任务并标记为已取消。运行中的任务向子进程组发送终止信号，等待短暂宽限期后再强制结束；当前实现约定宽限期为 3 秒。已完成的包不回滚。每个取消动作记录发生阶段和原因。

### 5.4 重试

仅以下错误自动重试：网络超时、代理断连、HTTP 服务端临时错误。最多自动重试 3 次，退避间隔为 5 秒、30 秒和 120 秒。

命令参数错误、权限错误、工具缺失、版本冲突和其他确定性错误直接失败。重试复用同一任务 ID，但每次尝试单独写入 `task_attempts`。

## 6. 包管理器适配器

每个适配器实现统一接口：

```text
detect()          检查工具、版本和可执行路径
scan()            读取已安装资源和可用更新
plan()            生成单资源或批量更新任务
execute()         执行更新并返回结构化结果
uninstall()       卸载单个资源并返回结构化结果
measure_disk()    测量单个资源的文件占用
classify_error()  将退出码和输出归类为可重试或确定性错误
```

### 6.1 Homebrew

管理 formula、cask 和 tap。`brew update` 的 tap 同步结果作为独立资源变化记录；formula 和 cask 支持单项与批量升级。所有 Homebrew 操作共用 `brew` 锁。

### 6.2 npm

只读取和更新全局 npm 包。适配器使用全局 outdated 信息生成包级任务，支持单包更新和批量更新，不读取项目目录。

### 6.3 pip

使用检测到的 Python 环境运行模块化 pip 命令，管理该环境中的全局包。适配器不访问项目目录，不修改项目配置和 lock 文件；Python 环境路径和权限问题作为明确错误显示。

### 6.4 Gem

只读取和更新当前 `gem` 可执行文件对应 Ruby 环境中的全局 gems。适配器使用全局 outdated 信息生成 gem 级任务，支持单 gem 更新和批量更新，不读取 Bundler 项目，不修改 `Gemfile` 或 lock 文件，也不自动使用 `sudo` 修改系统 Ruby。

### 6.5 rustup

管理已安装的 Rust 工具链、组件和目标平台，使用 rustup 的统一更新流程。首版不管理 `cargo install` 二进制，不自动安装 `cargo-update`。

所有适配器都提供资源级卸载：Homebrew formula/cask 使用对应 uninstall，tap 使用 untap；npm 使用全局 uninstall；pip 使用当前 Python 环境的 uninstall；Gem 使用 gem uninstall；rustup 对工具链、组件和 target 分别使用对应 remove/uninstall 操作。卸载必须经过确认对话框，不提供跨生态一键卸载；卸载结果进入日志和历史。

如果工具不存在、版本不满足或命令能力不适用，适配器返回结构化的“不适用”或“工具缺失”状态，而不是执行猜测性的兼容命令。

## 7. 代理系统

设置中只保存一个代理配置：直连/代理模式、SOCKS5 主机、端口，以及可选用户名和密码。代理模式开启时，任务不得静默降级为直连。

- 支持 SOCKS5 或 `ALL_PROXY` 的命令直接注入 SOCKS5 配置。
- 只支持 `HTTP_PROXY`/`HTTPS_PROXY` 的命令通过 Rust 内置 HTTP-to-SOCKS5 桥接器访问代理。
- 不支持代理环境变量的命令由适配器标记为“不支持统一代理”，不执行隐式直连。

HTTP 桥接器按批次按需启动，只绑定 `127.0.0.1` 的随机临时端口。它支持普通 HTTP 请求和 HTTP CONNECT，通过 SOCKS5 转发并使用远程 DNS 解析；批次结束且无连接后关闭。桥接启动失败、代理认证失败和连接超时归类为代理可重试错误。

代理健康检查验证 SOCKS5 握手、可选认证和目标连通性。健康检查结果写入批次摘要，但不写入密码或完整代理 URL。

## 8. 配置、持久化与安全

SQLite 数据库位置为：

```text
~/Library/Application Support/updaddy/updaddy.sqlite
```

逻辑表包括：

- `settings`：主题、语言、代理模式、计划设置、生态显示开关和日志配置
- `worker_state`：每个生态 worker 的启用、运行状态和最后事件序号
- `manager_profiles`：工具检测结果、路径和启用状态
- `package_snapshots`：最近扫描的包和版本
- `disk_usage_cache`：生态、软件包身份、安装路径/版本、占用字节数和扫描时间
- `operation_batches`：手动/计划更新或卸载批次摘要
- `package_tasks`：包级更新/卸载任务、状态、重试和错误
- `task_attempts`：每次执行尝试和退出信息
- `log_entries`：结构化日志和输出片段
- `scheduler_state`：周期标识、上次执行时间和补执行状态

### 8.1 磁盘占用缓存

缓存键由生态、软件包唯一身份、安装根路径和已安装版本组成，并记录实际扫描路径、字节数、扫描时间和测量状态。首次扫描时为发现的每个软件包计算占用；后续扫描命中相同缓存键时直接读取缓存，不重复遍历文件系统。

以下情况只重新扫描受影响的软件包：

- 缓存中没有该软件包。
- 软件包版本、安装根路径或实际安装路径发生变化。
- 软件包更新成功后。
- 用户在对应生态 tab 中显式请求刷新该软件包的占用。

扫描发现软件包已经卸载时，删除对应缓存项；不对其他软件包做全量重算。磁盘扫描使用有界并发，避免首次扫描大量软件包时占满磁盘 I/O。占用以字节保存，前端显示人类可读单位，并用原始字节值排序。

各适配器按其实际安装布局确定测量路径：

- Homebrew formula 统计 Cellar 安装目录，cask 统计已安装 app/artifact 路径，tap 统计 tap 仓库目录。
- npm 统计全局 root 下对应软件包目录。
- pip 根据 distribution metadata 枚举该软件包文件并按唯一文件路径求和。
- Gem 根据 gemspec 文件清单和 gem 安装目录统计文件大小。
- rustup 以工具链根目录作为占用统计单位；组件和 target 作为工具链的子资源展示并标记“已包含于工具链”，不重复累计同一文件。

无法定位安装路径时，缓存记录“不可用”状态和原因，前端不显示伪造的大小。

写入使用事务，数据库和父目录权限限制为当前用户可读写。代理凭据按已确认的方案存储在 SQLite 中，不使用 macOS Keychain；这是文件权限保护，不等同于系统密钥库保护，设置页面应明确提示该风险。

安全控制：

- 密码输入不回显。
- 凭据不进入命令日志、错误摘要、状态栏文本或诊断导出。
- 输出中的认证 URL、令牌和私密路径片段在写入数据库前脱敏。
- HTTP 桥接器永远不监听局域网地址。
- 前端把命令输出作为文本渲染，不拼接为 HTML。

应用启动时，停留在“运行中”的任务被标记为“中断”，不会自动重复可能有副作用的更新；用户可以手动重试。计划任务使用独立周期标识判断补执行，避免重复创建。

每天在启动或调度器唤醒时清理超过 90 天的批次、尝试记录和详细日志，保留配置和最新包快照。SQLite 使用版本化迁移，应用升级时不覆盖用户设置。

## 9. 界面、主题与多语言

主窗口的核心导航为：

- `概览`：五个生态的总状态、合计待更新数、最近结果和全局“一键更新”。
- `Homebrew`：formula、cask、tap。
- `npm`：全局 npm 包。
- `pip`：Python 全局包。
- `Gem`：全局 gems。
- `rustup`：工具链、组件和目标平台。
- `历史与日志`：跨生态批次、任务尝试和详细输出。
- `设置`：包管理器、代理、计划、启动、语言和主题。

主窗口工具栏提供设置入口；状态栏菜单也提供同一个设置入口，两者打开相同的设置页面。

每个生态使用独立 tab，包含自己的扫描按钮和一个软件包列表。列表列出软件包名称、当前版本、目标版本、磁盘占用、状态和操作；待更新软件包的操作栏提供独立“更新”按钮，每个软件包的操作栏都提供“删除/卸载”按钮。默认排序为待更新软件包在前、其余软件包在后，同组内按名称排序。用户点击“磁盘占用”列后，对整个列表按字节数升序或降序排序，待更新项可以与其他项混排；再次选择默认排序才恢复待更新优先。

点击卸载按钮后必须弹出确认对话框，显示生态、软件包名称、当前版本和预计操作。确认后进入对应生态 worker；确认前不会执行任何命令。更新和卸载互斥，同一软件包不能同时存在两个活动操作。

磁盘占用正在计算时显示明确的计算中状态；命中缓存时直接显示缓存值。全局一键更新只创建跨生态批次，实际执行由统一调度器控制。

任意生态存在扫描、更新或卸载任务时，前台所有扫描、更新、卸载、刷新和一键更新按钮置灰。正在执行任务的生态 tab 顶部固定显示进度条、当前操作和取消按钮；取消按钮保持可用。导航、日志查看和窗口关闭仍然可用，设置中的会改变任务行为的控件在任务结束前暂时置灰。

设置页分为两个 tab：

- `常规`：主题、直连/SOCKS5 代理、每日/每周固定时间、开机启动以及五个生态的显示开关。
- `日志`：查看结构化日志和任务输出，配置日志级别、是否保留完整命令输出，并提供立即清理过期日志的入口；自动保留周期仍固定为 90 天。

生态显示规则由 worker supervisor 执行：检测不到包管理工具时该生态默认隐藏；用户隐藏生态后暂停完整扫描、暂停其计划更新，并从概览和状态栏总数排除。应用每次启动仍对隐藏生态执行轻量 `detect()`，但不扫描包列表、不测量磁盘占用；用户重新显示生态后才启动完整扫描。

主题只支持跟随系统、浅色和深色。界面为扫描、无更新、未安装、不适用、执行中、部分成功、失败和取消提供明确状态；任务进度变化不能改变列表基本尺寸或造成布局跳动。

语言资源全部放在项目根目录的 `lang/`：

```text
lang/en.yaml
lang/zh_CN.yaml
```

首版支持英文和简体中文。用户手动选择优先于系统 locale；未选择时跟随系统语言，不匹配时回退到英文。运行时加载当前语言和英文回退语言。缺失翻译键显示英文并只在开发日志中记录。新增语言沿用 `lang/<locale>.yaml` 命名方式，不需要修改组件代码。

## 10. 状态栏、登录项与计划生命周期

状态栏使用 macOS 模板图标，适配浅色和深色菜单栏。菜单包含：

- 显示所有五个生态合计的待更新数量；例如“可更新 12 项”。没有更新时显示“已是最新”，扫描中显示“正在检查更新…”。点击后始终打开“概览”。
- 手动一键更新
- 打开主窗口
- 设置
- 退出

关闭主窗口只隐藏窗口，不停止状态栏、调度器或后台任务。退出时取消尚未开始的任务，终止运行中的子进程，写入最终状态后结束进程。应用不发送 macOS 原生通知，结果只通过状态栏和主窗口显示。

开机自动运行使用 macOS 原生登录项注册机制。启用后登录时启动后台应用并显示状态栏图标，不自动打开主窗口；关闭设置会撤销登录项，不需要管理员权限。

计划支持固定每日或每周时间。到达时间后先重新扫描，再基于新快照创建批次。Mac 睡眠期间计时器暂停，唤醒或应用下次启动时根据周期标识判断是否错过计划；当前周期未补执行时立即执行一次，同一周期不重复补执行。运行中的手动批次不会被计划任务重复创建，计划任务等待当前批次结束后重新扫描。

## 11. 日志、历史与错误展示

每个批次记录类型、时间、耗时、生态、任务数量、成功/失败/取消/跳过统计、代理健康检查结果和任务明细。任务明细包含包级状态、每次重试、标准输出、错误输出、退出码和取消原因。

历史页面按时间、生态、批次类型和最终状态筛选。失败任务重试前先重新扫描对应生态，确认目标版本仍存在，再创建新的尝试；不会盲目复用过期版本。网络、代理、工具缺失、权限和版本冲突等错误使用可操作的中文/英文摘要呈现，原始命令输出只在任务详情中查看。

## 12. 测试与发布验收

### 12.1 Rust 单元测试

覆盖版本和包列表解析、错误分类、重试退避、资源锁、取消状态转换、每日/每周补执行、代理配置解析、日志脱敏、磁盘占用缓存命中/失效、SQLite 迁移和 90 天清理。调度器使用可控时钟，不依赖真实等待。

### 12.2 适配器集成测试

使用假命令和固定输出模拟 `brew`、`npm`、`pip`、`gem`、`rustup`，验证工具缺失、正常扫描、更新成功、卸载成功、非零退出码、网络/代理临时错误、确定性错误、取消和结构化日志。测试不修改开发机真实全局环境。

### 12.3 前端和 Tauri 契约测试

验证五个生态 tab、单列表默认待更新优先、逐包更新和卸载按钮、卸载确认、磁盘占用排序、概览总数与状态栏总数一致、隐藏生态暂停与启动轻量探测、一键更新、全局按钮置灰、tab 顶部进度和取消、重试、历史展开、主题、语言回退及各种空/失败状态。验证 Tauri command 参数和 Tauri 事件到前端状态的映射，不使用前端轮询。

### 12.4 macOS smoke test

在最新 macOS Apple Silicon 上验证状态栏图标、窗口隐藏、登录项、睡眠唤醒补执行、代理桥接 loopback 监听、代理失败不直连、退出时任务终止、应用重启后的历史与中断状态恢复。

发布前执行 Rust 和前端依赖审计、敏感信息扫描，并只发布 Apple Silicon 架构产物。
